# CLI 레퍼런스

로버 펌웨어를 빌드·플래시하고, 시리얼 터미널로 조작하는 방법.

---

## 1. PC에서 실행하는 명령

### 빌드 / 플래시

```bash
cd ~/ksrc/firmware/src2026-rover-firmware

./build.sh              # 빌드만
./build.sh --flash      # 빌드 후 ST-Link로 플래시
./build.sh --clean      # build/ 지우고 전체 재빌드
```

`arm-none-eabi-gcc`가 PATH에 없으면 CubeIDE에 번들된 툴체인을 자동으로 찾습니다. CubeIDE를 열 필요 없습니다.

### 시리얼 터미널

```bash
python3 -m serial.tools.miniterm /dev/ttyACM0 115200
```

나가기: `Ctrl+]`

ST-Link의 가상 COM 포트입니다. 보드와 PC를 잇는 USB 케이블 하나가 **플래시와 터미널 둘 다** 담당합니다.

### 조이스틱 텔레오퍼레이션

```bash
python3 ~/ksrc/pi/teleop/teleop_joystick.py
```

| 인자 | 기본값 | 설명 |
|---|---|---|
| `--port` | `/dev/ttyACM0` | 시리얼 장치 |
| `--baud` | `115200` | 보레이트 |
| `--rate` | `20.0` | 명령 전송 주기(Hz). 30 넘기면 펌웨어 파서가 바이트를 흘리기 시작 |
| `--format` | `ascii` | `ascii`=실제 로버(`V ...` 줄), `binary`=시뮬레이터 |
| `--max-lin` | `0.5` | 패드 최대 변위에 대응하는 \|vx\|,\|vy\| (m/s) |
| `--max-ang` | `2.0` | 패드 최대 변위에 대응하는 \|ω\| (rad/s) |

조작: 왼쪽 패드 드래그=병진, 오른쪽 패드=회전, `Q`/`E`=회전(병진과 동시 가능), `Space`=정지, `Esc`=종료.

시뮬레이터에 붙일 때만 `--format binary`를 씁니다.

## 2. 터미널 명령어

대소문자 구분 없음. 한 줄 입력 후 엔터.

### 화면 / 도움말

| 명령 | 인자 | 설명 |
|---|---|---|
| `LOG` | 없음 | 주기 로그 + 모터 테스트 단계 메시지 on/off **토글**. 기본 ON |
| `ECHO` | 없음 | 입력 문자 에코 on/off **토글**. 기본 ON |
| `HELP` | 없음 | 명령 목록 |

> **작업 시작할 때 `LOG` 한 번** 치고 시작하세요. 기본 상태에서는 엔코더 로그가 0.1초마다 5줄씩, 모터 테스트 단계 메시지가 1~2초마다 쏟아져 입력도 응답도 읽을 수 없습니다. `LOG`를 끄면 완전히 무음이 되고, 내가 친 글자와 명령 응답만 보입니다. 토글이라 리셋 전까지 유지됩니다.

**에코**: 펌웨어가 받은 문자를 되돌려 보내므로 타이핑이 그대로 화면에 보이고, **백스페이스로 오타를 고칠 수 있습니다**. 터미널 프로그램(miniterm / screen / PuTTY)과 무관하게 동작합니다. 터미널 자체의 로컬 에코를 쓰고 있어 글자가 두 번 보인다면 `ECHO`로 끄세요.

> 텔레옵(`V` 명령)이 시작되면 에코는 **자동으로 꺼집니다.** 조이스틱이 초당 수백 문자를 보내는 동안 ISR 이 송신을 기다리면 수신 오버런이 나기 때문입니다.

### 서보 탐색 / 설정

| 명령 | 인자 | 설명 |
|---|---|---|
| `PING` | 없음 | ID 1~4 응답 확인 |
| `SCAN` | 없음 | ID 1~253 전체 스캔. 약 4초, 실행 중 모터 정지 |
| `ID <현재> <새>` | 현재 0~254, 새 0~253 | 서보 ID 변경 |
| `ZERO <id\|ALL>` | id 1~253 또는 `ALL` | 현재 자세를 0도로 영점 기록 |

**`ID` 주의**: 반드시 **서보를 1개만 연결한 상태**에서 실행하세요. 여러 개가 물린 채로 하면 전부 같은 ID가 됩니다. `254`는 브로드캐스트라 현재 ID를 몰라도 됩니다 — `ID 254 3`.

**`ZERO` 주의**: 서보 EEPROM에 기록되어 전원을 꺼도 유지됩니다. 실행 전에 `OFF`로 토크를 풀고 바퀴를 물리적으로 정면 정렬해야 합니다.

### 조향 제어

| 명령 | 인자 | 설명 |
|---|---|---|
| `ON` / `OFF` | 없음 | 토크 켜기 / 끄기. 끄면 손으로 돌릴 수 있음 |
| `T <a1> <a2> <a3> <a4>` | 각도(도), 최대 4개 | 조향각 직접 지정. 준 개수만큼만 전송 |
| `P` | 없음 | 현재 조향각 읽기 |
| `S <속도>` | 정수, step/s | 서보 이동 속도. `0`=최대 |

`T`는 인자 개수만큼만 명령을 보냅니다 — `T 30`은 1번 서보에만, `T 0 30`은 1·2번에만. 각도는 `joint.c`의 `min_deg`/`max_deg`(기본 ±90°)로 클램프됩니다.

### 기구학 주행

| 명령 | 인자 | 설명 |
|---|---|---|
| `V <vx> <vy> <ω>` | **정확히 3개** | 몸체 속도 → 4모듈 조향각+구동 duty 자동 계산 |

좌표계: **x=전진, y=좌측, ω=반시계(+)**. 단위는 m/s, m/s, rad/s.

```
V 0.1 0 0      전진
V 0 0.1 0      왼쪽 게걸음
V 0 0 1.5      제자리 반시계 회전
V 0 0 0        정지
```

동작 특성:
- **첫 `V` 명령에서 모터 자동 테스트 시퀀스가 중단**되고 에코가 꺼집니다. 되돌리려면 보드 리셋. (모터를 조용히 세우고 수동 작업만 하고 싶을 때도 `V 0 0 0` 이 유용합니다)
- **워치독**: 마지막 `V` 이후 500ms 동안 명령이 없으면 모터를 정지시킵니다. 조이스틱이 끊겨도 로버가 계속 굴러가지 않도록 하는 안전장치입니다.
- 디버그 출력은 5Hz로 제한됩니다(명령 처리는 full rate). 안 그러면 115200 baud가 포화됩니다.

## 3. 브링업 순서

배선 후 처음 한 번 하는 작업입니다.

```
LOG                 화면 정리 (이후 완전 무음, 타이핑이 보임)
SCAN                버스에 뭐가 몇 번으로 잡혀 있나 확인
```

`SCAN` 결과가 비어 있으면 → 배선(PB10/GND), 서보 12V 전원, 보레이트를 확인하세요.

**ID 부여** (전부 ID=1로 나왔을 때. 서보 하나씩만 연결):

```
ID 254 4            연결된 서보 1개를 4번으로
                    → 분리하고 다음 서보 연결
ID 254 3
ID 254 2
ID 254 1
                    → 4개 전부 데이지체인 연결
SCAN                1·2·3·4 다 잡히는지 확인
```

높은 번호부터 부여하면 중간에 중복이 생겨도 덜 꼬입니다.

**영점 + 방향**:

```
OFF                 토크 풀기
                    → 자를 대고 바퀴 4개를 정면으로 정렬
ZERO ALL            지금 자세를 0도로 기록
ON                  토크 켜기
T 0 0 0 0           4개 다 정면 보면 성공
T 30 0 0 0          1번이 위에서 볼 때 반시계로 돌아야 정상
```

반대로 돌면 `Core/Src/joint.c`의 해당 서보 `dir`을 `-1`로 바꾸고 다시 빌드·플래시하세요. 4개 각각 확인해야 합니다. 좌우 대칭으로 장착했다면 한쪽은 `-1`이 되는 게 정상입니다.

**주행 확인**:

```
V 0.1 0 0           전진
V 0 0 0             정지
```

## 4. 자주 겪는 것

**포트는 한 번에 한 프로그램만 잡습니다.** `miniterm`이 `/dev/ttyACM0`을 열고 있으면 조이스틱 스크립트가 못 엽니다. 조이스틱 돌리기 전에 터미널을 닫으세요.

**USB는 STM32만 먹입니다.** 모터(12V)와 서보(12V)는 별도 전원입니다. USB만 꽂은 상태에서는 명령을 쳐도 프린트만 나오고 아무것도 움직이지 않습니다 — 정상입니다. 배선 검증 단계에서는 오히려 안전합니다.

**서보 VCC를 STM32에 연결하지 마세요.** 12V 외부 전원에만 직결하고, GND만 공통으로 묶습니다.

**`No debug probe detected`** → ST-Link가 USB에 안 잡힌 것입니다. `lsusb | grep 0483`으로 확인하세요. 안 보이면 케이블 문제일 가능성이 높습니다(충전 전용 케이블은 데이터선이 없어 아예 인식되지 않습니다).

**`PING`이 전부 FAIL** → 서보 전원·배선·ID를 확인하세요. 서보를 연결하지 않았다면 정상 결과입니다.

## 5. 아직 실측값이 아닌 것

다음 값들은 임시값이라 실제 측정 후 교체해야 합니다.

| 항목 | 위치 | 현재 값 |
|---|---|---|
| 모듈 장착 위치 | `main.c` `SWERVE_MODULES` | ±0.12 m (트랙·휠베이스 240mm 가정) |
| 최대 바퀴 속도 | `main.c` `SWERVE_MAX_WHEEL_MPS` | 0.3 m/s |
| 모듈↔모터/서보 매핑 | `main.c` `SWERVE_MODULE_MOTOR` | 0→MOTOR1 … 3→MOTOR4 (실제 배선 미확인) |
| 조향 원점·방향 | `joint.c` `joint_config[]` | offset=2048, dir=+1 (캘리브레이션 전) |

모듈 위치와 최대 속도가 틀려도 방향은 맞고 크기만 어긋납니다. 반면 **원점·방향·매핑이 틀리면 로버가 엉뚱한 방향으로 갑니다.**
